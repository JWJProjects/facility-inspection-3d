# 巡場｜驗收方法

以固定情境版號交付一次，重跑時使用全新工作階段。以下是驗收方法，不等同已通過。測試結果必須標示執行環境、桌面或逐點模式、是否使用實際匯出的遊戲，並分開列出跳過及阻塞項。

| 測項 | 操作與判準 |
|---|---|
| AC-01 編輯交接 | 在 Three Studio 0.6.0 開啟交付的原始專案。查看設備 GLB、照明、場景物件、玩家起點及門／牆碰撞；移動一個無關裝飾再還原，確認設計可修改且 Player 啟動。 |
| AC-02 門與碰撞 | 初始區按 E，門不開。貼近閉門往前不能穿門；靠近後按一次 E，看狀態更新並自主走過門框；不把跨場景時的位置預設當作玩家已通過門。 |
| AC-03 巡檢閉環 | 查閱 P-02 模擬狀態，提交前故意留一個必填欄位；確認可定位並補完，而後摘要及下載的 JSON 站點、異常、模式、版本相符；重置後沒有上一輪異常或摘要。 |
| AC-04 靜態匯出 | 在不安裝 Three Studio 的瀏覽器，以靜態 HTTP 開啟；分別測根路徑及非根路徑、記錄 WebGPU 或 WebGL2 能力、確認無資源 404。驗證方式是實際操作，不只是 HTTP 200。 |
| AC-05 鍵盤與小螢幕 | 使用 Tab／Shift+Tab／Enter，並以螢幕閱讀器語意檢查逐點流程；390 px 無水平溢位，200% 放大與減少動態獨立驗收。不把逐點模式當成手機 3D 已通過。 |
| AC-06 展示驗證 | 真實遊戲和桌面編輯器畫面各附至少一張；逐點模式附 390 px 截圖。記錄本案與組織其他案的差異、對比與 compare，預覽核准後才推公開分支。 |
